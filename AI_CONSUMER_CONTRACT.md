# ServiceTitan Bridge API: Connection Guide for AI Consumers

This document outlines how an AI consumer (like Muse or Gus) should connect to the ServiceTitan Bridge. The Bridge acts as a secure, authenticated proxy between you and the ServiceTitan API. 

**You do not need ServiceTitan client IDs, secrets, or app keys. You only need a single Bridge API key.**

## 1. Authentication & Base URL
All requests must be directed to the Bridge API, not ServiceTitan directly.

- **Base URL:** `https://servicetitanbridge.vercel.app/v1`
- **Authentication:** Provide the Bridge API Key in the standard Authorization header.
  - `Authorization: Bearer <YOUR_BRIDGE_API_KEY>`

*(Note: The Bridge API Key should be injected dynamically from your secret vault. Do not hardcode it.)*

## 2. Reading Data (The GET Proxy)
You have broad read access to ServiceTitan through the Bridge's proxy route. The Bridge automatically attaches the necessary ServiceTitan tenant IDs and OAuth tokens behind the scenes.

To perform a GET request against ServiceTitan, prepend `/proxy/` to the ServiceTitan namespace and path.

**Format:** 
`GET /proxy/{namespace}/{rest-of-path}?{query}`

**Examples:**
- Read Customers: `GET /proxy/crm/customers?page=1&pageSize=50`
- Read Jobs: `GET /proxy/jpm/jobs?status=Completed`

**Rules for Reads:**
- Only `GET` is supported. (PUT/POST/PATCH/DELETE will return 405 Method Not Allowed).
- Allowed namespaces: `crm`, `jpm`, `dispatch`, `accounting`, `payroll`, `timesheets`, `pricebook`, `inventory`.
- Do not attempt to supply a Host, Tenant ID, or ServiceTitan App Key. The Bridge handles this.

## 3. Writing Data (Explicit Mutations)
Writes are strictly controlled. You cannot use the `/proxy` route for mutations. Instead, you must use specific named routes provided by the Bridge. 

**Rules for Writes:**
- Every `POST` request must include an `Idempotency-Key` header (a unique UUID/string generated by you) to prevent duplicate executions if a request retries.
  - `Idempotency-Key: <unique-uuid-per-action>`
- Send the payload as `application/json`.

**Available Mutation Endpoints:**

### Create a Job
`POST /jobs`
Payload:
```json
{
  "customerId": 123,
  "locationId": 456,
  "businessUnitId": 78,
  "jobTypeId": 90,
  "priority": "Normal",
  "summary": "Job description here"
}
```
*(Optional fields: `scheduledWindow`, `assignedTechnicianIds`, `initialNotes`)*

### Add a Job Note
`POST /jobs/{jobId}/notes`
Payload:
```json
{
  "text": "Customer approved the revised arrival window.",
  "pinToTop": false
}
```

### Add an Appointment to a Job
`POST /appointments`
Payload:
```json
{
  "jobId": 321,
  "start": "2026-09-24T14:00:00Z",
  "end": "2026-09-24T16:00:00Z",
  "arrivalWindowStart": "2026-09-24T14:00:00Z",
  "arrivalWindowEnd": "2026-09-24T16:00:00Z",
  "technicianIds": [1001, 1002],
  "specialInstructions": "Call before arrival."
}
```

### Create a Draft Estimate
`POST /estimate-drafts`
Payload:
```json
{
  "jobId": "321",
  "name": "Garage door replacement",
  "summary": "Draft created by AI",
  "items": [
    { "skuId": "789", "quantity": "1", "unitPrice": "0.00" }
  ]
}
```

## 4. Error Handling
- `401 Unauthorized`: Your Bridge API Key is missing or invalid.
- `409 Conflict`: You submitted a `POST` request using an `Idempotency-Key` that has already been used for a completely different payload.
- `429 Too Many Requests`: You are exceeding the Bridge's strict rate limits. Observe the `Retry-After` header.
- `502 Bad Gateway`: The Bridge encountered a timeout or error when communicating with the upstream ServiceTitan API.
